* Emacsの構築

** 構成

init.el と conf/ 以下の *.el は役割で分割している。新しい設定を足すときは、この分類に沿って該当ファイルに追記する。

*** init.el

最小限のブートストラップだけを担当する。
- ロケール・文字コードの設定
- straight.el 自体のブートストラップ(パッケージマネージャ本体の導入)
- custom.el の読み込み
- load-path の追加
- conf/ 以下の各ファイルを、依存順に ~load~ する

*** conf/*.el

機能ごとに分割していて、init.el から次の順(依存順)で読み込まれる。

| ファイル              | 役割                                                                                          |
|-----------------------+-----------------------------------------------------------------------------------------------|
| basic.el              | フォント・見た目・Dired基本設定・バックアップ設定・PATH同期など、Emacs本体の基礎設定。パッケージへの依存が薄い設定が中心。 |
| package-manage.el     | straight.el/use-packageによる各種パッケージの導入・設定(evil、補完(corfu/orderless/prescient)、Magit、vterm、gptel等)。プログラミング言語以外の汎用パッケージはここに集約する。 |
| language.el           | プログラミング言語・マークアップ/データ形式のメジャーモード、および言語サーバ(eglot)・Lintの設定。                    |
| mylisp.el             | 既存パッケージに依存しない自作のユーティリティ関数(OS標準アプリで開く、Boxnote作成 等)。                             |
| keybind-manage.el     | 全てのキーバインド定義。パッケージ設定側にキーバインドを書かず、ここに集約して一覧性を保つ。                           |

load順が重要になる場合がある(例: keybind-manage.el は package-manage.el で定義された関数・キーマップを参照するため最後に読み込む)。

** パッケージ管理の思想

- パッケージマネージャは package.el/ELPA ではなく [[https://github.com/radian-software/straight.el][straight.el]] を使用している。
  - gitのコミット単位でバージョンを固定でき、~straight/versions/default.el~ の lockfile をコミットすることで別マシンでも同一状態を再現できる(ELPA/MELPAはバージョンの巻き戻し・固定がしづらい)
  - MELPAに存在しないパッケージもGitHubから直接取得できる(例: ~:straight (corfu :type git :host github :repo "minad/corfu" ...)~)
- パッケージの導入・設定は [[https://github.com/jwiegley/use-package][use-package]] で統一している。~:straight t~ を必ず付け、~:defer~/~:hook~/~:commands~ などで遅延読み込みし起動時間を抑える。
- 1つのuse-packageブロックにキーバインドをベタ書きせず、キーバインドは keybind-manage.el 側にまとめる。設定(何を有効化するか)とキー割り当て(どのキーで呼ぶか)を分離することで、キーバインドの一覧性・変更のしやすさを保っている。
- lockfileの更新(新しいパッケージ追加後や、意図的な最新化)は下記「別マシンへの移行」を参照。

** 初回起動(パッケージの事前ダウンロード)

新しいマシンでの初回起動は、straight.el が lockfile 記載の全パッケージ(約90個)を clone/build するため時間がかかる。特に GUI(Emacs.app)から起動するとダウンロード中は画面が無反応になり「固まった」ように見える。下記の手順で *シェルから事前取得* しておくと、進捗がターミナルに出て、GUI をロックせずに済む。

*** 手順

1. (推奨) recipe リポジトリ nongnu-elpa を軽量取得しておく
   straight は既定で nongnu-elpa を [[https://git.savannah.gnu.org][git.savannah.gnu.org]] から *全ブランチ* clone する。savannah は帯域が細く、これが初回フリーズの主因。単一ブランチ・浅い clone にしておけば数秒で済み、straight は origin URL が一致するためこれをそのまま使う(重い再取得をしない)。

   #+begin_src sh
   mkdir -p ~/.emacs.d/straight/repos
   git clone --single-branch --depth 1 \
     https://git.savannah.gnu.org/git/emacs/nongnu.git \
     ~/.emacs.d/straight/repos/nongnu-elpa
   #+end_src


2. init.el が参照する空ディレクトリを用意する(無いと load-path 構築で停止する)

   #+begin_src sh
   mkdir -p ~/.emacs.d/public_repos
   #+end_src


3. バッチ(非GUI)でパッケージを一括 clone / build する

   #+begin_src sh
   emacs --batch -l ~/.emacs.d/init.el
   #+end_src

   straight.el のブートストラップ → 各パッケージの clone/build が進み、進捗がターミナルに出る。~EXIT 0~ で終われば ~straight/repos/~ に約90個のリポジトリが揃う。事前に PATH へ go/npm 等を通した状態で実行すると、言語サーバ連携まわりの警告も減る。


4. 通常どおり GUI で起動する。パッケージは取得済みなので固まらない。

*** Emacs 30 対応(設定側で対処済み)

Emacs 30 では pin している一部パッケージがそのままでは動かないため、設定側で対処している(新規に lockfile を作り直す際も同様の対処が要る)。

- ~init.el~: straight.el が参照する ~native-comp-deferred-compilation-deny-list~(Emacs 30 で削除)を、未定義なら補う互換シムを bootstrap 前に定義している。これが無いと straight のネイティブコンパイル時に ~void-variable~ で停止する。
- ~conf/package-manage.el~: git-gutter+ が依存宣言する git-commit の recipe が現行 recipe リポジトリから消滅した(magit に統合された)ため、magit リポ内の ~lisp/git-commit.el~ を指す recipe を明示して解決させている。


*** transient / magit の "static-when" エラー(原因と修正)

起動時に次のような警告が出ることがある(use-package が捕捉するため起動自体は継続する)。

#+begin_example
Invalid function: static-when
transient--init-suffix-key is already defined as something else than a generic function
#+end_example

**原因**: transient / magit は compat 由来のマクロ ~static-when~ を使う。ところが straight が
~build-cache.el~ にこれらの依存を =nil= と記録してしまうことがあり(特にビルドが途中で中断された
場合)、その状態でビルドすると compat が load-path に入らないまま byte-compile され、~static-when~
が *展開されず関数呼び出しとして .elc に残る*。起動時に「Invalid function: static-when」で transient
のロードが不完全になり、Emacs 30 組込 transient(0.7.x)と ~transient--init-suffix-key~ の定義が
衝突して magit / magit-section / git-gutter+ まで巻き込む。

**修正**: 依存(compat/cond-let/llama 等)を読み込んだ状態で該当パッケージを byte-compile し直す。
~static-when~ を使うのは ~transient.el~ と ~magit-base.el~ だが、道連れになる magit 一式もまとめて
再コンパイルすると確実。

#+begin_src sh
emacs --batch --eval '(let ((b (expand-file-name "~/.emacs.d/straight/build/")))
  (dolist (p (directory-files b t))
    (when (file-directory-p p) (add-to-list (quote load-path) p)))
  (dolist (r (quote (compat cond-let llama dash with-editor))) (ignore-errors (require r)))
  (dolist (pkg (quote ("transient" "magit" "magit-section" "git-commit" "with-editor" "git-gutter-plus")))
    (dolist (el (directory-files (expand-file-name pkg b) t "\\.el$"))
      (ignore-errors (byte-compile-file el)))))'
#+end_src

再コンパイル後に Emacs を再起動すれば解消する。~.el~ ソースは変更しないので straight は再ビルドせず、
この修正した ~.elc~ がそのまま使われる(~straight/build~ を消して作り直すと再発しうる)。

*** 言語サーバー(eglot)を使う場合

Emacs30標準の eglot で、プログラミング言語ごとに言語サーバーを自動起動する設定を language.el に入れている。Emacs自体には同梱されていないため、使いたい言語の分だけ別途インストールする(未インストールでもEmacsの起動やそれ以外の言語の編集には影響しない)。

| 言語       | 実行ファイル                 | インストール例                                                |
|------------+-------------------------------+----------------------------------------------------------------|
| Python     | pyright                      | ~npm install -g pyright~                                       |
| TypeScript | typescript-language-server   | ~npm install -g typescript typescript-language-server~         |
| Go         | gopls                        | ~go install golang.org/x/tools/gopls@latest~                   |
| Rust       | rust-analyzer                | ~rustup component add rust-analyzer~ (要rustupでのRust導入)     |
| Shell      | bash-language-server         | ~npm install -g bash-language-server~                          |

(macOS注意) Emacs.appなどGUIから起動したEmacsは、ターミナルの ~.zshrc~ 等で設定したPATHを引き継がない。npmのグローバルインストール先や ~~/.go/bin~ 等に上記を入れてもeglotが見つけられないことがあるため、basic.el で [[https://github.com/purcell/exec-path-from-shell][exec-path-from-shell]] を使いシェルのPATHをEmacsに同期している(通常は追加設定不要)。

** Emacsビルドの切り替え (NS Emacs 30 ⇔ emacs-mac 29)

macOSでは2つのEmacsを共存させ、用途で使い分けている。設定はビルドごとに *git ブランチ* を分けている。

| ビルド        | Homebrew          | CLI(~emacs~)         | GUI                          | 設定ブランチ   | indent 表示            |
|---------------+-------------------+----------------------+------------------------------+----------------+------------------------|
| NS Emacs 30   | ~emacs~ + ~emacs-app~ | ~brew link emacs~        | ~/Applications/Emacs.app~      | ~main~           | highlight-indent-guides |
| emacs-mac 29  | ~emacs-mac@29~      | ~brew link emacs-mac@29~  | ~/Applications/Emacs-mac29~(別名) | ~emacs-mac29~    | indent-bars(stipple)    |

両者は Cellar に併存でき、CLI の ~emacs~ はどちらか一方だけが ~/opt/homebrew/bin/emacs~ を張れる(リンクの排他)。

*** 切り替え手順(両方向で対称)

30→29 と 29→30 は *ミラーの同一手順* で、入れ替える formula 名と checkout するブランチが逆になるだけ。

1. CLI のリンクを張り替える(現行を unlink → 対象を link)

   #+begin_src sh
   # 30 → 29
   brew unlink emacs        && brew link emacs-mac@29
   # 29 → 30
   brew unlink emacs-mac@29 && brew link --overwrite emacs
   #+end_src

2. 設定ブランチを切り替える

   #+begin_src sh
   git checkout emacs-mac29   # 29用 (30へ戻すときは main)
   #+end_src

3. GUI は対象のアプリを起動する(~/Applications/Emacs.app~ = 30、~/Applications/Emacs-mac29~ = 29)。

*** 手順が完全に同じにならない点(emacs-mac 29 側だけの追加事項)

2つのビルドは native-comp の有無が異なるため、29 側にだけ前提・注意がある。

- *gcc(native-comp)*: emacs-mac 29 は native-comp 有効。~.eln~ のリンクに gcc のランタイムが要るので
  ~brew install gcc~ が前提(未導入だと "ld: library 'emutls_w' not found" で失敗)。
  NS Emacs 30(この emacsformacosx ビルド)は native-comp *無効* なので gcc 不要・~eln-cache~ も作られない。
- *初回起動の重さ*: 29 へ切り替えた初回は native-comp が走り重い(~eln-cache/29.4-*~ を生成)。30 側は無い。
- *~straight/build~ は共有*: ~.elc~ は両ビルドで共有される。通常はそのまま読めるが、挙動が怪しいときは
  ~straight/build~ を作り直す。特に切替直後に transient/magit のエラーが出たら、上の
  「transient / magit の "static-when" エラー」の再コンパイルを実行する。

まとめると、*骨格の手順(link 張り替え + ブランチ切替 + アプリ起動)は両方向で同じ* で、
29 側にだけ「gcc が要る・初回が重い」という差がある。

** 別マシンへの移行 (straight.el)

パッケージは straight.el で管理しており、~straight/versions/default.el~ にバージョンを固定した lockfile をコミットしている。

- 新しいMacでの初回起動時、init.el が straight.el 自身をbootstrapし、各パッケージを lockfile に記録されたコミットで取得する
- lockfile を更新したいとき（新しいパッケージを追加した/意図的に最新化したいとき）は、Emacs上で ~M-x straight-freeze-versions~ を実行してから差分をコミットする
- straight関連のエラーで詰まったときは、まず ~M-x straight-thaw-versions~ でlockfile通りの状態に戻せるか試す
- 「ローカルのgit remoteとレシピのURLが食い違う」旨のエラーが出た場合、該当パッケージが上流でリポジトリ移動した可能性が高い。~straight/repos/<package>~ と ~straight/build/<package>~ を削除して再起動すれば再取得される
